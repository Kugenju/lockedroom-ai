# ScriptMurder 设计文档

日期：2026-11-10
状态：待确认
目标：求职简历项目（1 个月完整版 + 长期维护）

## 1. 问题陈述

现有开源 AI 剧本杀项目（ai-murder-mystery、jubensha-ai 等）普遍存在两个被忽视的痛点：

1. **剧透不可控**：角色 Agent 的 prompt 包含全局真相，模型"嘴瓢"说出不该知道的事，且没有量化手段衡量；玩家体验被随机毁局。
2. **对局无沉淀**：游戏结束即丢失一切，没有结构化回放、推理过程评估，玩家不知道自己"差在哪"，开发者无法评估剧本难度和 Agent 表现。

ScriptMurder 以「信息隔离与防剧透引擎」（InfoGuard）和「复盘评估系统」（ReplayEval）为核心差异化，构建可量化、可回放、可评估的多智能体剧本杀平台。

## 2. 已确认决策

| 决策点 | 结论 |
|--------|------|
| 技术栈 | Python 全栈：FastAPI + React 18/TS/Vite，前后端分离 |
| 玩家模式 | 单人玩家 + AI 角色群（嫌疑人/目击者/凶手均由 AI 扮演） |
| LLM 接入 | OpenAI-compatible 抽象层，DeepSeek 为主 + Ollama 本地兜底，可扩展任意兼容端点 |
| 时间预算 | 1 个月完整版，模块化设计以支持长期维护 |
| 建设方式 | 从零实现，借鉴开源项目的设计思想（不复制代码），保持简历可信度 |

## 3. 核心系统架构

```
backend/ (FastAPI)
├── api/                 # REST + WebSocket 路由：game / script / replay / eval
├── core/
│   ├── engine/          # 游戏阶段状态机（背景→自我介绍→搜证→讨论→指认→真相）
│   ├── agents/          # 角色 Agent：prompt 组装 + LLM 调用 + 记忆
│   ├── infoguard/       # 【差异化1】信息隔离与防剧透引擎
│   ├── replayeval/      # 【差异化2】复盘与评估系统
│   └── llm/             # 多后端抽象（OpenAI-compatible / Ollama）
├── models/              # Pydantic schema + SQLAlchemy ORM
└── scripts/             # 剧本 YAML 库
frontend/ (React + TS + Vite)
├── pages/               # 大厅 / 游戏 / 回放 / 报告
└── components/          # 对话流 / 线索板 / 时间线回放 / 评估图表
```

数据库：SQLite（开发）/ PostgreSQL（生产），事件流持久化支撑回放。

### 3.1 InfoGuard：信息隔离与防剧透引擎

**威胁模型**——剧透的三个来源：

| 来源 | 场景 | 防御层 |
|------|------|--------|
| 输入侧 | prompt 注入了角色不应知道的信息 | L1 静态作用域 |
| 生成侧 | 模型主动说出禁止信息（嘴瓢） | L2 输出检测 |
| 上下文侧 | 对话历史/玩家发言带出的间接泄露 | L3 运行时过滤 |

**L1 静态作用域（剧本编译期）**
- 剧本为结构化 YAML：`truths`（真相事实，每条有 fact_id）、`characters`（每个角色的 public_profile / own_secrets / known_fact_ids）、`clues`（线索，标注可见角色集合）
- 编译后为每个角色生成 `InformationScope`：公开事实 ∪ 自己的秘密 ∪ 明确允许知道的 fact_ids；**禁止清单** = 其余全部真相与秘密
- Prompt 组装器只按 scope 取料，凶手角色也拿不到其他角色的秘密全文

**L2 输出检测（生成后）**
- 一级：规则 + embedding 相似度，对禁止清单做匹配（n-gram 命中 + 向量阈值）
- 二级：LLM judge 判定泄露严重度（无泄露 / 软暗示 / 硬泄露）
- 处理策略：硬泄露 → 触发重写（携带泄露告警重写一次）；软泄露 → 记录放行；重试仍泄露 → 降级为安全回复模板
- 每次判定记录 `LeakEvent{turn, character, fact_id, severity, action}`——这是评估系统的数据源

**L3 运行时上下文过滤**
- 每条进入角色上下文的消息先做信息标注（含哪些 fact_id、对当前角色是否敏感）
- 角色读取历史时按自己的 scope 过滤或摘要化；玩家跨角色套话得到的敏感信息不会回流到其他角色的上下文

### 3.2 ReplayEval：复盘与评估系统

**事件溯源（Event Sourcing）**：对局全程写入 `GameEvent` 流（消息、动作、泄露事件、阶段切换），回放 = 事件重放。

**四大评估产物**：
1. **时间线回放**：前端逐步重演对局，可高亮展示"哪句话发生了泄露事件""哪个线索在哪一步被发现"
2. **推理链提取**：LLM 从玩家动作序列提取推理链报告——关注了谁、忽略了什么关键线索、哪条信息促成结论
3. **量化指标**：
   - 泄露率（按严重度加权的事件数 / 总轮数）
   - 关键线索覆盖率（被玩家触及的关键线索 / 全部关键线索）
   - 指认正确率、动机匹配度
   - 剧本难度评分（线索熵 + 平均泄露率的组合）
4. **复盘报告**：markdown 导出（用于分享）+ 前端可视化

### 3.3 游戏引擎（支撑层）

阶段状态机：`背景介绍 → 自我介绍 → 搜证 → 自由调查（对话循环）→ 指认与动机 → 真相揭示 → 结算评估`
- 每个 AI 角色 = 独立 Agent（人格 prompt + scope 注入 + 对话记忆 + InfoGuard 管线）
- 搜证：线索库按阶段解锁，线索附带可见范围
- 流式输出（SSE/WebSocket）到 React 前端

## 4. MVP 范围（1 个月）

**做**：
- 完整游戏闭环（上述 7 阶段）
- InfoGuard 三层全部实现 + 针对泄露检测的单元/集成测试（防剧透是核心卖点，测试即简历材料）
- 事件流 + 时间线回放 + 推理链报告 + 核心指标
- 2 个打磨完整的中文剧本（经典暴风雪山庄 + 现代本格）
- LLM 抽象层（DeepSeek + Ollama）+ 流式对话
- Docker Compose 一键部署 + 架构 README

**暂不做（留作长期迭代）**：
- 多真人联机、语音（ASR/TTS）、AI 剧本生成器、证物组合系统、剧本可视化编辑器
